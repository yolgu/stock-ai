## 1. 조사 결과: FOMO와 가장 가까운 검증 개념

가장 가까운 연구 개념은 **Attention-driven buying**입니다. Barber & Odean은 개인투자자가 뉴스에 나온 종목, 비정상 거래량이 큰 종목, 하루 수익률이 극단적인 종목 같은 “관심을 끄는 종목”을 순매수하는 경향이 있다고 설명합니다. 이건 FOMO의 실전적 기반과 꽤 가깝습니다. ([SSRN][1])

더 직접적인 관심 지표로는 Google Search Volume Index, 즉 **SVI / ASVI**가 있습니다. Da, Engelberg, Gao는 Google 검색량을 투자자 관심의 직접 지표로 사용했고, ASVI를 `현재 주 로그 SVI - 직전 8주 로그 SVI 중앙값`으로 정의했습니다. 해당 연구에서는 SVI가 거래량, 극단 수익률, 뉴스보다 더 시의성 있게 관심을 포착할 수 있다고 설명합니다. ([Academic Web Service][2])

시장 전체 심리에는 VIX, put/call ratio, AAII sentiment survey 같은 지표가 쓰입니다. AAII도 일반적인 시장 심리 지표로 put-call ratio, fund flow, VIX, AAII survey, margin debt 등을 제시하지만, 단일 지표만으로 판단하면 안 된다고 설명합니다. ([AAII][3])

따라서 **개별 종목 FOMO 지수**는 아래처럼 보는 것이 좋습니다.

```text
FOMO = 관심 급증 + 가격 추격 + 상대강도 + 비정상 거래량 + 단기 콜옵션 수요 + 시장 위험선호
```

## 2. FOMO를 구하기 좋은 값

실전 우선순위는 이 순서입니다.

| 우선순위 | 값                                   | 왜 중요한가                                        |
| -------: | ------------------------------------ | -------------------------------------------------- |
|        1 | **ASVI / 검색량 급증**               | 실제 대중 관심을 가장 직접적으로 측정합니다.       |
|        2 | **Retail Buy Imbalance / CVD / OFI** | 관심이 실제 매수 체결로 바뀌었는지 확인합니다.     |
|        3 | **Abnormal Volume / Turnover**       | 갑자기 사람들이 몰렸는지 봅니다.                   |
|        4 | **단기 OTM·ATM 콜옵션 수요**         | FOMO성 레버리지 베팅을 포착합니다.                 |
|        5 | **상대강도: QQQ, SOXX 대비**         | 단순 시장 상승인지, 종목 자체 추격인지 구분합니다. |
|        6 | **고점 근접도 / VWAP 상단 이격**     | 추격 매수 위치인지 확인합니다.                     |
|        7 | **뉴스·소셜 언급량**                 | 관심의 촉매를 봅니다.                              |
|        8 | **VIX, 시장 put/call ratio**         | 시장 전체 위험선호를 봅니다.                       |

가장 좋은 조합은 **ASVI + 실시간 CVD/OFI + 콜옵션 수요 + 시간대별 거래량 페이스**입니다. 이번 웹 산출에서는 ASVI, 실시간 CVD, OFI, retail flow가 없어서 **Potential FOMO**, 즉 잠재 FOMO로만 계산했습니다.

## 3. 추천 공식

먼저 모든 값을 0~100으로 정규화합니다.

```text
norm(x, low, high)
= 100 × clip((x - low) / (high - low), 0, 1)
```

### 3-1. 검색 관심 지표

```text
ASVI_t
= log(SVI_t) - log(median(SVI_{t-1}, ..., SVI_{t-8}))
```

해석은 단순합니다.

```text
ASVI > 0 : 평소보다 검색 관심 증가
ASVI >> 0 : FOMO성 관심 급증 가능
ASVI < 0 : 관심 둔화
```

### 3-2. 거래량 페이스

```text
VolumePace
= (Volume_so_far / AvgDailyVolume)
  / ExpectedIntradayVolumeFraction(t)
```

```text
VolumePace > 1.0 : 평소보다 빠른 거래량
VolumePace > 1.5 : 관심 급증
VolumePace > 2.0 : FOMO/패닉 가능
```

### 3-3. 콜옵션 추격 수요

```text
CallShare
= CallVolume / (CallVolume + PutVolume)
```

```text
PutCallRatio
= PutVolume / CallVolume
```

해석은 이렇게 잡습니다.

```text
CallShare > 60% : 콜 수요 우위
CallShare > 70% : 투기적 콜 추격 가능성
PutCallRatio < 0.50 : 강한 낙관/콜 쏠림
PutCallRatio 0.50~0.80 : 낙관 우위
PutCallRatio 0.80~1.20 : 중립
```

CBOE도 put/call ratio 해석에는 가정이 필요하지만, 일반적으로 높은 put/call ratio는 불확실성, 낮은 ratio는 낙관을 나타낸다고 설명합니다. ([Cboe Global Markets][4])

### 3-4. 종목 FOMO 지수

```text
StockFOMO_Potential
= 0.18 × AttentionScore
+ 0.18 × MomentumChaseScore
+ 0.16 × RelativeStrengthScore
+ 0.16 × OptionsCallDemandScore
+ 0.12 × VolumePaceScore
+ 0.12 × MarketRiskAppetiteScore
+ 0.08 × IntradayChaseQualityScore
```

실시간 체결·호가가 있으면 최종값은 이렇게 보정합니다.

```text
BuyFlowConfirm
= 0.45 × BuyOFI
+ 0.35 × CVD_Acceleration
+ 0.20 × AggressiveBuyRatio
```

```text
StockFOMO_Final
= 0.65 × StockFOMO_Potential
+ 0.35 × BuyFlowConfirm
```

이번에는 `BuyFlowConfirm` 데이터가 없어서 최종 FOMO가 아니라 **Potential FOMO**로만 산출합니다.

## 2. 그래프만으로 FOMO를 알 수 있나?

가능한 부분과 불가능한 부분이 나뉩니다.

**가격+거래량 그래프만으로 알 수 있는 것**은 “FOMO처럼 보이는 추격 매수 행동”입니다. 예를 들면 이런 것들입니다.

```text
가격이 빠르게 상승한다
+ 거래량이 시간대 대비 비정상적으로 증가한다
+ 캔들이 고점 근처에서 마감된다
+ VWAP 위에서 오래 버틴다
+ 눌림이 얕고 바로 재상승한다
```

이건 그래프만으로도 꽤 잘 잡힙니다.

하지만 **진짜 투자자 심리로서의 FOMO**는 그래프만으로는 확정할 수 없습니다. 검색량, 뉴스 클릭, 커뮤니티 언급, 신규 매수자 비중, 옵션 콜 수요 같은 데이터가 있어야 더 직접적으로 알 수 있습니다. Da·Engelberg·Gao도 검색량은 직접 관심지표이고, 거래량·극단 수익률·뉴스는 간접 지표라고 구분했습니다. ([University of Notre Dame][2])

그래서 지표 이름도 정확히는 **FOMO Index**보다 아래처럼 두는 게 더 좋습니다.

```text
Chart-FOMO = 차트에서 관측되는 추격 매수 강도
Flow-FOMO = 체결·호가에서 확인되는 추격 매수 강도
Attention-FOMO = 검색·뉴스·소셜·옵션까지 포함한 관심 과열도
```

토스 API로 먼저 구현할 것은 **Chart-FOMO + Flow-FOMO**입니다.

## 3. 토스 API로 구현 가능한 핵심값

토스증권 Open API는 공식 소개 기준으로 **실시간 호가·체결 정보와 캔들 차트 데이터**를 다룰 수 있다고 안내되어 있습니다. 따라서 FOMO 지표의 핵심 입력값인 현재가, 분봉, 거래량, 체결, 호가 기반 지표는 구현 후보로 볼 수 있습니다. ([Toss Invest][5])

| 데이터             |         토스 API 구현 적합도 | FOMO 지표 사용                              |
| ------------------ | ---------------------------: | ------------------------------------------- |
| 1분봉/3분봉 OHLCV  |                         높음 | 가격 가속도, 거래량 서프라이즈, 고점 근접도 |
| 현재가             |                         높음 | VWAP 이격, 돌파 여부                        |
| 체결 내역          |                         높음 | aggressive buy/sell, CVD, 체결 속도         |
| 호가/orderbook     |                         높음 | OFI, OBI, 매도벽/매수벽 변화                |
| 시장 지수/섹터 ETF |                가능하면 사용 | 상대강도 필터                               |
| 옵션 콜/풋         | 토스 API 범위 밖일 가능성 큼 | 1차 FOMO 지표에서는 제외                    |
| 검색량/소셜/뉴스   |             토스 API 범위 밖 | 별도 Attention 모듈                         |

## 4. 더 나은 FOMO 지표 구조

기존처럼 하나의 점수에 모든 것을 섞기보다, 아래 3단 구조가 낫습니다.

```text
1) ChartFOMO
   캔들 + 거래량 + VWAP만으로 보는 추격 강도

2) FlowFOMO
   체결 + 호가로 실제 매수 압력이 확인되는지 보는 강도

3) FOMO_Tradability
   FOMO가 있더라도 스프레드/슬리피지/과열 리스크 때문에 거래 가능한지 보는 보정 점수
```

이렇게 나누면 “사람들이 몰리는 것처럼 보인다”와 “지금 따라붙어도 체결 품질이 괜찮다”를 분리할 수 있습니다.

# 5. 추천 공식: Graph/Chart-FOMO

먼저 모든 지표는 고정 임계값보다 **과거 동일 시간대 percentile**로 정규화하는 게 좋습니다.

```text
PercentileRank_t(x)
= x가 최근 N거래일의 동일 시간대 분포에서 몇 퍼센타일인지
```

예를 들어 10:15의 거래량은 10:15 과거 거래량과 비교해야지, 15:50 거래량과 비교하면 안 됩니다. 장중 거래량은 시간대별 패턴이 강하기 때문입니다. ([SSRN][3])

---

## 5-1. 가격 추격 강도

```text
ReturnImpulse_h
= PercentileRank(
    log(P_t / P_{t-h}) / RealizedVol_h
  )
```

해석:

```text
최근 h분 상승률이 평소 변동성 대비 얼마나 비정상적으로 큰가
```

FOMO에서 가장 먼저 봐야 할 값입니다. 단순 수익률보다 변동성으로 나눈 값이 더 낫습니다.

---

## 5-2. 가격 가속도

```text
ReturnAccel_h
= PercentileRank(
    r_t - mean(r_{t-h:t})
  )
```

또는 단순하게:

```text
PriceAccel_t
= P_t - 2P_{t-1} + P_{t-2}
```

FOMO는 단순 상승보다 **상승 속도가 빨라지는 구간**에서 강하게 나타납니다.

---

## 5-3. 거래량 서프라이즈

```text
VolumePace_h
= ActualVolume_{t-h:t}
  / ExpectedVolume_{same_time,h}
```

```text
VolumeSurprise_h
= PercentileRank(VolumePace_h)
```

여기서 `ExpectedVolume`은 최근 20~60거래일의 동일 시간대 평균 또는 중앙값을 씁니다.

이 값은 기존 글의 `VolumePaceScore`보다 더 좋습니다. 기존 방식처럼 단순히 현재 누적 거래량을 일평균 거래량과 비교하면 장 초반·장 마감 왜곡이 생깁니다.

---

## 5-4. 고점 추격 위치

```text
CloseLocation_n
= (P_t - RollingLow_n) / (RollingHigh_n - RollingLow_n)
```

```text
BreakoutStrength_n
= max(P_t - RollingHigh_{n, previous}, 0) / ATR_h
```

```text
RangeChaseScore
= 0.6 × CloseLocation_n
+ 0.4 × clip(BreakoutStrength_n, 0, 1)
```

해석:

```text
현재 가격이 최근 n분 범위의 상단에 붙어 있는가
돌파가 실제로 발생했는가
```

단, 이 값만 높다고 FOMO는 아닙니다. 거래량과 매수 체결이 같이 붙어야 합니다.

---

## 5-5. VWAP 추격 강도

VWAP는 장중 가격과 거래량을 함께 반영한 평균 가격입니다. Investopedia도 VWAP를 단일 세션에서 가격과 거래량으로 계산되는 평균 가격 지표로 설명하며, 유동성과 장중 가격 움직임을 보는 데 쓰인다고 설명합니다. ([Investopedia][6])

```text
VWAP_Extension
= max(P_t - VWAP_t, 0) / ATR_h
```

```text
VWAP_Persistence_h
= VolumeAboveVWAP_{t-h:t} / TotalVolume_{t-h:t}
```

해석:

```text
가격이 VWAP 위로 튀었는가
그 상태에서 거래량까지 동반되었는가
```

FOMO는 순간적으로 VWAP를 넘는 것보다 **VWAP 위에서 거래량이 계속 쌓이는 것**이 더 중요합니다.

---

## 5-6. 눌림 거부 강도

```text
PullbackHold_n
= 1 - clip((RollingHigh_n - P_t) / ATR_h, 0, 1)
```

해석:

```text
고점에서 크게 밀리지 않고 버티는가
```

FOMO성 장세에서는 사람들이 눌림을 기다리다가 못 사고, 얕은 눌림에서 바로 재매수합니다. 그래서 고점 대비 하락폭이 작고 거래량이 유지되면 FOMO 가능성이 커집니다.

---

## 5-7. ChartFOMO 최종식

토스 API의 분봉과 거래량만으로 구현할 수 있는 1차 공식은 아래가 적절합니다.

```text
ChartFOMO
= 100 × [
  0.24 × ReturnImpulse
+ 0.16 × ReturnAccel
+ 0.22 × VolumeSurprise
+ 0.16 × RangeChaseScore
+ 0.14 × VWAP_Persistence
+ 0.08 × PullbackHold
]
```

이 공식은 기존 글보다 낫습니다. 이유는 세 가지입니다.

첫째, 사람이 넣는 `AttentionScore`가 없습니다.
둘째, 옵션·뉴스·소셜 같은 토스 API 밖 데이터를 강제로 섞지 않습니다.
셋째, 시간대별 거래량 보정을 넣어 장 초반·장 마감 왜곡을 줄입니다.

# 6. 추천 공식: Flow-FOMO

차트만으로는 “추격처럼 보이는 상태”까지만 알 수 있습니다. 진짜 중요한 것은 **매수자가 공격적으로 때리고 있는지**입니다.

Order Flow Imbalance는 짧은 시간의 가격 변화와 관련성이 큰 지표로 연구되어 있습니다. Cont, Kukanov, Stoikov는 짧은 시간 구간에서 가격 변화가 최우선 bid/ask의 수요·공급 불균형인 OFI와 선형 관계를 보이며, 단순 거래량보다 더 견고하다고 설명합니다. ([arXiv][4])

---

## 6-1. 매수 체결 비율

체결 방향 필드가 있으면 그대로 쓰고, 없으면 ask/bid 근접도 또는 tick rule로 추정합니다.

```text
AggBuyRatio_h
= BuyVolume_h / (BuyVolume_h + SellVolume_h)
```

```text
AggBuyScore_h
= PercentileRank(AggBuyRatio_h)
```

---

## 6-2. CVD 기울기

```text
CVD_t
= Σ(BuyVolume_i - SellVolume_i)
```

```text
CVD_Slope_h
= (CVD_t - CVD_{t-h}) / TotalVolume_h
```

```text
CVD_Accel_h
= CVD_Slope_h - CVD_Slope_{previous h}
```

FOMO는 가격만 오르는 게 아니라 **CVD가 같이 올라야** 신뢰도가 높습니다.

---

## 6-3. OFI

최우선 bid/ask 기준 간단형은 이렇게 잡을 수 있습니다.

```text
OFI_t =
ΔBidSize_t × I(BidPrice_t >= BidPrice_{t-1})
- ΔAskSize_t × I(AskPrice_t <= AskPrice_{t-1})
```

실전 구현에서는 Cont 방식에 가깝게 bid/ask 가격 변화와 수량 변화를 반영하면 됩니다.

정규화:

```text
OFI_Score_h
= PercentileRank(OFI_h / AvgDepth_h)
```

---

## 6-4. OBI

```text
OBI_k
= (ΣBidSize_k - ΣAskSize_k)
  / (ΣBidSize_k + ΣAskSize_k)
```

```text
OBI_Score
= clip((OBI_k + 1) / 2, 0, 1)
```

OBI는 단독으로는 약합니다. 매도벽이 있어도 실제로는 흡수될 수 있고, 허수성 호가도 있을 수 있습니다. 그래서 OBI는 CVD/OFI 보조지표로만 쓰는 게 좋습니다.

---

## 6-5. FlowFOMO 최종식

```text
FlowFOMO
= 100 × [
  0.30 × AggBuyScore
+ 0.30 × CVD_SlopeScore
+ 0.20 × CVD_AccelScore
+ 0.15 × OFI_Score
+ 0.05 × OBI_Score
]
```

체결·호가 데이터가 없으면 `FlowFOMO`는 계산하지 않고 `ChartFOMO`만 출력해야 합니다.

---

# 7. 최종 FOMO 지표

토스 API로 구현할 최종 지표는 이렇게 두 단계로 두는 게 가장 깔끔합니다.

```text
FOMO_Intensity
= 0.60 × ChartFOMO
+ 0.40 × FlowFOMO
```

체결·호가가 없으면:

```text
FOMO_Intensity
= ChartFOMO
```

그리고 별도로 거래 가능성을 봅니다.

```text
SpreadRisk
= PercentileRank(SpreadPct)
```

```text
SlippageRisk
= PercentileRank(ExpectedSlippage)
```

```text
ExhaustionRisk
= 0.5 × UpperWickRatio
+ 0.5 × max(-CVD_AccelScore, 0)
```

```text
FOMO_Tradability
= FOMO_Intensity
- 15 × SpreadRisk
- 10 × SlippageRisk
- 10 × ExhaustionRisk
```

중요한 점은 **FOMO_Intensity와 FOMO_Tradability를 분리하는 것**입니다.

FOMO가 높다는 것은 “사람들이 몰리고 있다”는 뜻이지, “지금 사도 좋다”는 뜻이 아닙니다. 오히려 FOMO가 너무 높으면 윗꼬리·급반락 위험도 같이 커질 수 있습니다.

---

## 8. 점수 해석 기준

초기 기준은 이렇게 두고, 실제로는 과거 데이터로 보정해야 합니다.

|   점수 | 상태      | 해석                                            |
| -----: | --------- | ----------------------------------------------- |
|   0~30 | 낮음      | 추격 매수 흔적 약함                             |
|  30~50 | 관심 발생 | 가격/거래량 반응은 있으나 FOMO 아님             |
|  50~65 | 초기 FOMO | 추격성 매수 가능성 증가                         |
|  65~80 | 강한 FOMO | 돌파 지속 가능성과 과열 위험이 동시에 증가      |
| 80~100 | 극단 FOMO | 단기 급등 가능성도 있지만 윗꼬리·되돌림 위험 큼 |

매매에 바로 쓰려면 점수 하나보다 상태 조합이 중요합니다.

```text
좋은 FOMO:
ChartFOMO 높음
+ FlowFOMO 높음
+ SpreadRisk 낮음
+ VWAP 위 유지
+ CVD 상승
```

```text
나쁜 FOMO:
ChartFOMO 높음
+ FlowFOMO 둔화
+ 윗꼬리 증가
+ 스프레드 확대
+ CVD 하락
```

# 9. 기존 글의 “57점” 같은 산출 방식은 왜 위험한가

기존 글의 MU 57점은 리서치 예시로는 괜찮지만, 자동 지표로는 약합니다.

문제는 이 부분입니다.

```text
AttentionScore = 72
MarketRiskAppetiteScore = 74
RelativeStrengthScore = 54
IntradayChaseQualityScore = 47
```

이 숫자들이 명확한 산식 없이 들어가면, 나중에 원하는 결론에 맞게 점수를 바꿀 수 있습니다. 이게 사용자가 말씀하신 **보상해킹**에 가까운 구조입니다.

더 나은 방식은 아래처럼 해야 합니다.

```text
모든 점수 = 과거 동일 시간대 분포에서의 percentile
모든 입력값 = 현재 시점 t까지 관측된 데이터만 사용
가중치 = 백테스트 전에 고정
임계값 = 학습 구간에서만 정하고 검증 구간에서는 변경 금지
```

# 10. 과거 데이터 검증 방법

이 지표는 반드시 과거 데이터로 검증해야 합니다. 단, 검증 목표를 명확히 해야 합니다.

FOMO 지표가 예측해야 하는 것은 하나가 아닙니다.

```text
1) FOMO 지속
   점수 상승 후 가격이 추가 상승하는가

2) FOMO 과열
   점수 극단 후 윗꼬리/되돌림이 나오는가

3) 거래 가능성
   실제 스프레드와 슬리피지를 감안해도 진입 가치가 있는가
```

그래서 라벨도 3개로 나눠야 합니다.

---

## 10-1. 지속 라벨

```text
ContinuationLabel_{t,h} = 1
if FutureMaxReturn_{t:t+h} >= +0.5 × ATR_h
and FutureMinReturn_{t:t+h} > -0.3 × ATR_h
else 0
```

해석:

```text
FOMO 발생 후 위로 먼저 가는가
```

---

## 10-2. 과열/실패 라벨

```text
ExhaustionLabel_{t,h} = 1
if UpperWickRatio_future >= threshold
or P_{t+h} < VWAP_{t+h}
or FutureMinReturn_{t:t+h} <= -0.5 × ATR_h
else 0
```

해석:

```text
FOMO처럼 보였지만 실제로는 윗꼬리/되돌림이었는가
```

---

## 10-3. 거래 가능 라벨

```text
TradableLabel_{t,h} = 1
if MFE_after_cost >= 1.5 × MAE_after_cost
and SpreadPct_t <= historical_70pct
else 0
```

여기서:

```text
MFE = 진입 후 최대 유리 변동
MAE = 진입 후 최대 불리 변동
```

FOMO가 높아도 체결비용이 크면 실전에서는 의미가 없습니다.

---

## 10-4. 검증 지표

| 검증 항목     | 봐야 하는 값                                               |
| ------------- | ---------------------------------------------------------- |
| 단조성        | FOMO 1~5분위로 나눴을 때 미래 수익률/MFE가 단조 증가하는가 |
| 과열 위험     | 최상위 FOMO 구간에서 MAE와 윗꼬리 빈도가 같이 증가하는가   |
| AUC / PR-AUC  | ContinuationLabel 예측력이 있는가                          |
| Spearman IC   | FOMO 점수와 미래 수익률 순위가 관련 있는가                 |
| Calibration   | 70점 이상일 때 실제 지속 확률이 60점대보다 높은가          |
| 비용 반영 PnL | 스프레드·슬리피지 후에도 의미가 있는가                     |
| 안정성        | 종목, 시간대, 시장 레짐이 바뀌어도 유지되는가              |

단순히 “승률이 높다”만 보면 안 됩니다. FOMO는 급등 구간을 잡는 지표라서 승률보다 **MFE/MAE, 슬리피지, 윗꼬리 빈도**가 더 중요합니다.

## 11. 검증 시 보상해킹 방지 규칙

Bailey, López de Prado 등은 투자전략 백테스트에서 일반적인 hold-out 방식도 신뢰하기 어렵고, 여러 전략을 시험한 뒤 좋은 것만 고르는 백테스트 과최적화 문제가 크다고 설명하며 PBO, 즉 Probability of Backtest Overfitting 프레임워크를 제안했습니다. ([SSRN][7]) López de Prado의 금융 ML 프레임워크도 일반 K-fold가 금융 시계열에서 누수 문제를 만들 수 있어 Purged K-Fold와 Embargo 같은 방식을 다룹니다. ([PhilPapers][8])

실전 규칙은 이렇게 두시면 됩니다.

```text
1) 지표 공식과 가중치를 먼저 고정한다.
2) 과거 데이터를 보고 임계값을 계속 바꾸지 않는다.
3) 학습 구간, 검증 구간, 최종 테스트 구간을 분리한다.
4) 같은 이벤트가 train/test 양쪽에 걸치지 않게 purging/embargo를 둔다.
5) 한 종목이 아니라 여러 종목·여러 장세에서 본다.
6) 단순 모멘텀/거래량 돌파 전략보다 나은지 비교한다.
7) 결과가 좋아도 슬리피지와 수수료를 넣고 다시 본다.
```

가장 중요한 기준은 이겁니다.

```text
FOMO 지표가 단순히 “최근 오른 종목”을 다시 이름 붙인 것이라면 실패입니다.
```

따라서 반드시 아래 baseline과 비교해야 합니다.

```text
Baseline 1: 최근 5분 수익률
Baseline 2: 최근 5분 거래량 증가율
Baseline 3: VWAP 위/아래
Baseline 4: 전고점 돌파 여부
```

만약 FOMO 지표가 이 단순 기준보다 못하면 버려야 합니다.

# 12. 최종 추천 지표 사양

토스 API 구현용으로는 아래 구조가 가장 적절합니다.

```json
{
  "indicator_name": "TossChartFlowFOMO",
  "version": "0.1",
  "required_data": {
    "candles": ["timestamp", "open", "high", "low", "close", "volume"],
    "trades": ["timestamp", "price", "quantity", "side_or_estimated_side"],
    "orderbook": [
      "timestamp",
      "bid_price_levels",
      "bid_size_levels",
      "ask_price_levels",
      "ask_size_levels"
    ]
  },
  "chart_fomo_components": {
    "return_impulse": "percentile_rank(log(P_t/P_t-h)/realized_vol_h)",
    "return_acceleration": "percentile_rank(r_t - mean(r_t-h:t))",
    "volume_surprise": "percentile_rank(actual_volume_h / expected_volume_same_time_h)",
    "range_chase": "0.6*close_location_n + 0.4*breakout_strength_n",
    "vwap_persistence": "volume_above_vwap_h / total_volume_h",
    "pullback_hold": "1 - clip((rolling_high_n - P_t)/ATR_h, 0, 1)"
  },
  "flow_fomo_components": {
    "aggressive_buy_score": "percentile_rank(buy_volume_h / total_trade_volume_h)",
    "cvd_slope_score": "percentile_rank((CVD_t - CVD_t-h) / total_volume_h)",
    "cvd_acceleration_score": "percentile_rank(CVD_slope_h - CVD_slope_prev_h)",
    "ofi_score": "percentile_rank(OFI_h / average_depth_h)",
    "obi_score": "clip((OBI_k + 1) / 2, 0, 1)"
  },
  "formula": {
    "chart_fomo": "100*(0.24*return_impulse + 0.16*return_acceleration + 0.22*volume_surprise + 0.16*range_chase + 0.14*vwap_persistence + 0.08*pullback_hold)",
    "flow_fomo": "100*(0.30*aggressive_buy_score + 0.30*cvd_slope_score + 0.20*cvd_acceleration_score + 0.15*ofi_score + 0.05*obi_score)",
    "fomo_intensity": "0.60*chart_fomo + 0.40*flow_fomo",
    "fomo_tradability": "fomo_intensity - 15*spread_risk - 10*slippage_risk - 10*exhaustion_risk"
  },
  "validation_required": {
    "labels": ["continuation", "exhaustion", "tradability"],
    "methods": [
      "walk_forward",
      "purged_kfold",
      "embargo",
      "out_of_sample_test"
    ],
    "metrics": [
      "spearman_ic",
      "auc",
      "pr_auc",
      "mfe_mae",
      "cost_adjusted_pnl",
      "quintile_monotonicity"
    ]
  }
}
```

## 최종 판단

아래 글의 FOMO 지표는 **개념 설명으로는 쓸 만하지만, 자동매매/데이트레이딩 지표로는 그대로 쓰면 안 됩니다.**

가장 크게 바꿔야 하는 점은 세 가지입니다.

```text
1) 수동 AttentionScore 제거
2) 옵션·뉴스·시장위험선호는 FOMO 본체가 아니라 외부 컨텍스트로 분리
3) 차트 기반 FOMO와 체결/호가 기반 FOMO를 분리한 뒤 과거 데이터로 검증
```

그래프만으로는 **진짜 감정으로서의 FOMO**는 알 수 없습니다. 하지만 매매에 필요한 **추격 매수 행동으로서의 FOMO**는 가격, 거래량, VWAP, 고점 근접도, 체결 압력, OFI/CVD로 충분히 프록시화할 수 있습니다.

토스 API 구현용 최종 방향은:

```text
ChartFOMO = 그래프만으로 보이는 추격 강도
FlowFOMO = 체결·호가로 확인되는 실제 매수 압력
FOMO_Tradability = 따라붙어도 되는 체결 환경인지
```

이 3개를 따로 출력하는 방식이 가장 안전합니다.
