# MS-001 메타-메타연구 보고서

## 결론

**타입이 있는 파일 우선 연구객체 구조를 채택한다.** Markdown의 사람 사용성을 유지하면서 `object.json`, 최소 catalog, 자동 구조검사로 추적성과 변경 격리를 확보한다. RO-Crate와 PROV-O는 지금 완전 구현하지 않고 향후 교환 adapter의 목표계약으로 사용한다.

| --- | ---: | ---: | ---: | ---: |

## 선택 이유

### 평면 문서를 선택하지 않은 이유

읽기는 쉽지만 질문·프로토콜·실행·근거·결정의 책임이 문서마다 섞이고, 중복 ID와 깨진 의존성을 자동 검출하기 어렵다. 기존 문서가 이미 충분히 많기 때문에 더 많은 평면 문서를 추가하는 것은 탐색 비용을 증가시킨다.

### 완전 시맨틱 패키지를 즉시 선택하지 않은 이유

RO-Crate와 PROV-O는 상호운용성과 계보에 가장 강하지만, 현재 단계에서 RDF/OWL·JSON-LD 전체 구현과 외부 repository 운영은 연구 자체보다 문서 인프라 비용을 크게 만든다. 점수는 높지만 도입비용과 사람 사용성이 낮다.

### 파일 우선 객체를 선택한 이유

- 기존 저장소와 Git 흐름을 유지한다.
- v1.4를 이동하지 않고 wrapper 객체로 참조할 수 있다.
- 공통 descriptor가 최소 타입계약을 제공한다.
- catalog는 탐색점을 제공하면서 객체 정의를 복제하지 않는다.
- 검증기가 구조적 오류를 즉시 거부한다.
- 향후 descriptor를 RO-Crate JSON-LD와 PROV-O로 변환할 수 있다.

## 객체지향·DDD 적용 결과

- `governance`, `catalog`, `objects`, `templates`, `archive`, `tools`를 bounded context로 분리했다.
- 각 객체 폴더를 aggregate root로 삼았다.
- descriptor는 identity와 관계를 캡슐화한다.
- 다른 객체의 내용을 복제하지 않고 ID에 의존한다.
- 공통 schema를 합성하고 클래스 상속 계층은 만들지 않았다.
- 연구결론 검증과 구조검증의 책임을 분리했다.

## 채택한 표준의 최소 부분

- FAIR: 고유 ID, 검색 catalog, metadata, 재사용 조건
- RO-Crate: 폴더 기반 research object와 동반 descriptor
- PROV-O: 객체·실행·파생관계를 분리하는 개념
- OSF: 편집 가능한 상태와 동결 등록 상태 분리
- ACM: repeatability, reproducibility, replicability 구분
- PRISMA-ScR: 출처선정과 보고 한계를 명시하되 이번 조사를 정식 범위고찰로 과장하지 않음

상세 연결은 [근거행렬](evidence-matrix.md)과 [출처 원장](../../../governance/source-register.md)에 있다.

## 한계와 반증 가능성

- 후보 점수는 한 조사자의 구조적 판단이며 사용자 연구시간을 실제 측정한 값이 아니다.
- 외부 연구자가 이 구조로 연구를 재현할 수 있는지는 아직 검증되지 않았다.
- 객체 수가 크게 증가하면 JSON catalog와 파일 탐색의 성능·편의가 떨어질 수 있다.
- 외부 교환 요구가 커질 경우 RO-Crate를 보류한 결정은 재검토해야 한다.

다음 조건 중 하나가 관측되면 구조를 재평가한다.

- 객체 50개 이상에서 탐색·검증 시간이 실질적 병목이 됨
- 서로 다른 도구와 교환하기 위해 같은 metadata 변환을 세 번 이상 수동 작성함
- 연구자가 descriptor와 Markdown의 중복을 반복적으로 만들게 됨
- 독립 재현자가 catalog만으로 필요한 artifact를 찾지 못함

## 후속 결정

첫 적용대상은 `RP-001` 정량 시장행동·상대가치·실행 연구 프로그램이다. 새 모형을 구현하기 전에 질문지도, 관측가능성, 독립 study 포트폴리오와 통합 계약을 먼저 보존한다.
